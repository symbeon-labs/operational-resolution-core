# ORC Brandbook — Draft

Status: **working visual system**

The ORC visual identity should communicate **capture, resolution, progress and operational clarity**.

It must not visually reduce the product to e-commerce, inventory software or a generic AI assistant.

## 1. Core symbol

The ORC symbol combines four ideas:

1. **Scan frame** — the physical/digital world entering the system.
2. **Resolution ring** — multiple observations converging toward a resolved state.
3. **Check** — successful resolution, not a claim that every observation is true.
4. **Completion arc** — visible operational progress.

The symbol is intentionally abstract enough to represent the ORC layer beyond QR codes, labels or shopping carts.

Primary vector asset:

~~~text
assets/orc-symbol.svg
~~~

## 2. Semantic reading

The symbol should be read as:

> **capture → resolve → complete**

Not:

> buy → sell → checkout.

This distinction is important for product positioning.

## 3. Visual language

### Form

- rounded geometry;
- continuous strokes;
- strong negative space;
- modular construction;
- no unnecessary detail;
- recognizable at small sizes.

### Color

The working palette uses functional color roles:

- near-black: environment / background;
- cyan: capture, observation, input;
- green: resolution, confirmation, valid progression;
- amber: intermediate state / attention;
- red: conflict, interruption or unresolved condition.

The colors should communicate state rather than decoration.

### Typography

Working direction:

- clean sans-serif for operator-facing UI;
- monospaced or compact technical typography for identifiers, diagnostics and machine-readable references;
- short labels;
- high information hierarchy.

No final font family is established yet.

## 4. UI relationship

The symbol is not a decorative logo pasted onto every screen.

It becomes a **state language**:

~~~text
CYAN     → capturing / observing
GREEN    → resolved / confirmed
AMBER    → incomplete / attention
RED      → conflict / blocked resolution
~~~

The application should use these states consistently.

## 5. Motion

Motion should be functional and restrained.

Examples:

- capture frame gently closes around an object;
- resolution ring completes progressively;
- check mark appears only after resolution;
- conflict state interrupts the progression.

Avoid continuous decorative animation.

## 6. Gamification relationship

The visual system supports moderate gamification by representing operational progress.

The symbol's completion arc can become a progress metaphor.

The product should not rely on:

- coins;
- badges as the primary mechanic;
- arbitrary points;
- public rankings;
- excessive celebrations.

The preferred mechanic is **visible resolution progress**.

## 7. Logo usage

Preferred:

- app icon;
- splash/launch screen;
- empty states;
- completion states;
- operational dashboard identity;
- documentation and product materials.

Avoid:

- placing the symbol behind dense data;
- shrinking it until the semantic geometry disappears;
- recoloring it arbitrarily by screen;
- adding text inside the symbol;
- using the symbol as a QR replacement.

## 8. Brand principle

> **The interface should make operational resolution feel simple, visible and trustworthy.**

The visual identity should express the infrastructure without exposing its complexity to the operator.
